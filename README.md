# 台股熱度追蹤器

查詢台股**任意標的的名稱與代號**，並追蹤它在**網路上的討論熱度與多空情緒**。
涵蓋上市與上櫃全市場約 2,400 檔股票與 ETF，每日收盤後在本機批次更新，
結果以網頁儀表板呈現。全部使用免費資料來源，不需要任何 API 金鑰。

## 這個工具想回答的問題

熱度排行榜其實沒什麼用——台積電永遠第一，看一百天都一樣。
真正有價值的是**「今天誰突然被討論了」**：某檔平常沒人理的股票，今天的討論量是平常的五倍。

所以系統對每檔標的同時輸出兩個數字：

| 指標 | 意義 | 怎麼用 |
|---|---|---|
| **熱度分數** | 當日討論量在全市場的百分位（0–100） | 看量級與排名 |
| **異常倍數** | 相對自己過去 30 天基準的標準差倍數 | **真正的訊號**，+2 以上值得注意 |

儀表板首頁主打的是「異常竄升榜」而不是熱度排行，原因就在這裡。

## 功能

- **全市場標的查詢**：輸入代號、簡稱或公司名稱片段，涵蓋上市與上櫃的股票與 ETF
- **討論熱度**：以 PTT Stock 板為主要來源，加上 Google News 新聞則數
- **多空情緒**：推噓比搭配台股用語詞典，輸出看多／偏多／中性／偏空／看空
- **異常竄升偵測**：以個股自身 30 日基準做 z-score，找出突然被討論的標的
- **自選清單**：預設 30 檔，可在介面上增刪
- **比對稽核**：每個熱度數字都能點開看是由哪些文章、以什麼理由構成的

## 安裝（Windows）

需要 Python 3.11 以上。若尚未安裝，請到 [python.org](https://www.python.org/downloads/windows/) 下載，
安裝時務必勾選 **Add Python to PATH**。

在專案資料夾開啟命令提示字元：

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -e .
```

## 首次建庫

```bat
REM 1. 建立資料庫並抓取全市場標的主檔（約 30 秒）
stockheat init

REM 2. 回補近 30 天的 PTT 討論資料（約 15 至 25 分鐘）
stockheat backfill

REM 3. 開啟儀表板
scripts\run_dashboard.bat
```

回補是這個流程裡唯一耗時的步驟。實測 30 天約需走訪 110 個索引頁、下載 2,100 篇文章，
並以對站方友善的節奏送出請求。**中途可以直接關掉，重跑 `stockheat backfill` 會接續未完成的部分**，
已下載的文章不會重複抓。

### 想先看看介面再決定要不要等

```bat
python tools\seed_demo.py
set STOCKHEAT_DB=data\demo.db
.venv\Scripts\streamlit run app\dashboard.py
```

這會產生一份合成資料寫進 `data\demo.db`，不會動到正式資料庫。

## 每日更新

台股 13:30 收盤，交易所盤後資料稍晚才齊，建議排在 15:30 之後。

```powershell
# 以系統管理員身分開啟 PowerShell
powershell -ExecutionPolicy Bypass -File scripts\setup_schedule.ps1
```

這會在工作排程器建立一個平日每日執行的工作。也可以隨時手動跑：

```bat
scripts\run_daily.bat
```

增量更新約三到五分鐘完成。每次都會重新走訪整個 30 天的索引頁，
並重抓最近三天的文章——推文會持續累積，不重抓的話當天的互動量會被低估，
讓每一天看起來都比前幾天冷，直接扭曲異常倍數。

## 常用指令

| 指令 | 用途 |
|---|---|
| `stockheat init` | 建立資料庫、更新全市場標的主檔與別名 |
| `stockheat backfill` | 首次建庫，回補 30 天討論資料 |
| `stockheat daily` | 每日增量更新 |
| `stockheat search 台積電` | 命令列查詢標的與當前熱度 |
| `stockheat prices 2330` | 回補個股歷史股價（首次建庫時線圖才有東西） |
| `stockheat watchlist --add 6669` | 調整自選清單 |
| `stockheat rematch` | 調整消歧規則後重跑比對與計分，不必重新爬取 |

## 資料來源

| 來源 | 用途 | 說明 |
|---|---|---|
| [證交所 OpenAPI](https://openapi.twse.com.tw/) | 上市標的與行情 | 免金鑰 |
| [櫃買中心 OpenAPI](https://www.tpex.org.tw/openapi/) | 上櫃標的與行情 | 免金鑰 |
| PTT Stock 板 | 討論熱度與情緒 | 主要來源 |
| Google News RSS | 新聞則數 | 免金鑰 |
| Google Trends | 搜尋熱度 | **預設關閉**，見下方說明 |

### 關於 Google Trends

`pytrends` 已於 2025 年 4 月封存，Google 官方 Trends API 至今仍是限量 alpha。
現行替代品 `trendspyg` 需要本機安裝 Chrome，單次查詢要十幾到九十秒且極易觸發 429，
不可能涵蓋全市場 2,400 檔。因此這項功能預設關閉，啟用後也只會對自選清單與
當日熱度前 20 名執行。

```bat
pip install -e ".[trends]"
```

再把 `src/stockheat/config.py` 裡的 `TrendsConfig.enabled` 改成 `True`。

## 系統怎麼運作

```
證交所 / 櫃買 OpenAPI ──→ 標的主檔 + 別名生成
                              │
PTT Stock 板全板爬取 ──→ 本地文章庫 ──→ Aho-Corasick 比對 ──→ 提及紀錄
                                                                │
Google News RSS ──────→ 新聞紀錄 ───────────────────────────────┤
                                                                ▼
                                              每日聚合 → z-score → 熱度與情緒
                                                                ▼
                                                      Streamlit 儀表板
```

### 為什麼是「爬全板」而不是「逐檔搜尋」

要支援全市場，不可能對 2,400 檔各發一次搜尋請求。做法是反過來：
把整個看板爬下來建成本地文章庫，再用 Aho-Corasick 自動機一次掃描，
同時找出所有標的的提及。這讓支援全市場的邊際成本趨近於零，
對 PTT 的請求量也壓到最低。比對吞吐量約每秒 6 萬篇。

### 名稱比對的難處

全市場的名稱空間必然重疊，系統針對幾個真實會發生的誤判做了防護：

| 陷阱 | 例子 | 處理方式 |
|---|---|---|
| 年份撞代號 | `2024` 志聯、`2025` 千興、`2026` 志剛都是真實股票 | 後接「年」「Q1」等一律排除 |
| 日期黏連 | `20260807` 不該切出 `2026` | 代號兩側不得為數字 |
| 短名被長名包含 | 「南亞科技」裡的「南亞」不是 1303 | 最長命中優先 |
| 通用詞簡稱 | 「世界」「創意」「數字」是日常用語 | 需同篇出現代號，或命中衍生長別名 |
| 跨公司撞名 | 「南亞」同時是 1303 與 2408 的別名 | 自動偵測並升到最嚴格層級 |
| 名稱後綴 | `國巨*`、`臻鼎-KY` | 比對前正規化，顯示時保留 |
| 裸代號撞數字 | 內文的「1783」多半是指數點位或股價 | 只有 ETF 與標題中的代號才採計 |

其中「通用詞」無法用字串規則推導，只能靠詞彙清單。內建清單涵蓋約 150 個詞，
其中一部分是從 30 天真實 PTT 資料實測找出來的——例如「時報」會被「工商時報」
與「即時報導」誤中，「力士」被「SK海力士」誤中，「系統」被「作業系統」誤中。
遇到漏網之魚可以在儀表板的**比對稽核**頁一鍵加入，會寫進 `data\generic_names_user.yaml`，
套件更新不會覆蓋。加入後執行 `stockheat init` 與 `stockheat rematch` 生效。

### 兩個影響很大的資料清理

**排除彙整文。** PTT Stock 板每個交易日都有「上市外資買賣超排行」這類貼文，
一次列出 100 檔股票的代號與名稱。它們形式上是高信心命中，實質上完全不是討論，
卻天天為大型股墊高基準。實測 30 天資料中，**這類文章佔了全部提及的 73%**。
系統把提及超過 12 檔的文章視為彙整文，排除於熱度與情緒之外（仍保留在資料庫供查閱）。
提及 2 到 12 檔的文章則按注意力分攤，同時談 6 檔時每檔分到的份量少於專講 1 檔。

**週末歸到下一個交易日。** 週末討論量只有平日的六分之一。若當成獨立日期計入
30 日基準，會把基準整體拉低約三成，於是每個平日看起來都異常熱、每個週末都異常冷。
週末貼文談的本來就是下一個交易日，因此併入下週一計算。

### 情緒是怎麼算的

不使用預訓練模型，這是刻意的選擇。開源的繁體中文金融情緒分類器並不存在
（FinBERT2 是簡體語料的預訓練骨幹，需自行微調），而通用中文情感模型在股板語境下
會系統性判錯：「軋空」是大利多、「畢業」是慘賠出場、「住套房」跟房地產無關。

改用兩個訊號加權：

- **推噓比**（權重 0.65）：PTT 的推與噓本身就是台股散戶情緒的天然標註，準確且零成本
- **台股用語詞典**（權重 0.35）：涵蓋約 90 個多空用語，含否定詞反轉（「不看好」）

提及數少於 3 則時標記為「樣本不足」，不給假精確的判斷。

## 已知限制

- **PTT 改版會讓解析失效**。解析器有 fixture 測試，改版時 `pytest tests/test_ptt_parser.py` 會先失敗，比從熱度數字反推容易定位。
- **冷門股沒有資料是正常的**。全市場約 2,400 檔，PTT Stock 板 30 天內實際被討論的通常只有數百檔。
- **首次建庫沒有股價歷史**。每日批次只存當天的全市場快照，要立刻補齊線圖請執行 `stockheat prices <代號>`。
- **新聞只涵蓋自選與熱度前段班**。Google News RSS 是逐關鍵字查詢，成本與標的數成正比。
- **情緒是啟發式的**，不是模型推論。它抓得到明確表態，抓不到反諷與複雜語氣。
- **國定假日未特別處理**。只有週六日會併入下一個交易日，農曆年這類長假仍會被當成一般交易日納入基準。

## 開發

```bat
pip install -e ".[dev]"
pytest
ruff check .
```

測試涵蓋 PTT 解析、消歧規則、標的正規化與計分這四個最容易出錯也最影響結果的部分。
消歧測試裡的每個案例都對應一種真實發生過的誤判。

## 專案結構

```
src/stockheat/
  universe/     標的主檔：交易所資料拉取、名稱正規化、別名生成
  collectors/   採集器：ptt、news_rss、prices、trends
  matching/     Aho-Corasick 比對與消歧
  scoring/      熱度聚合、z-score、情緒計算
  storage/      SQLite schema 與資料存取
  resources/    詞典、通用詞清單、預設自選
  pipeline.py   每日批次與首次建庫流程
  cli.py        命令列入口
app/            Streamlit 儀表板
scripts/        Windows 批次檔與排程設定
tools/          示範資料產生器
```
